# 5Trade — Audit d'architecture (lecture seule)

Date : 2026-11-02 · Périmètre : dépôt `nocodescreen-dev/5trade` @ `main` · Méthode :
lecture du code, graphe des `require()`, requêtes SQL sur la base locale et sur la
base de production, aucune modification.

## 1. Arborescence réelle

    api/          58 modules JS · 2 monolithes (server.js 3 920 l., verify.js 3 589 l.)
    frontend/     10 fichiers · index.html 351 Ko (React+Babel via CDN)
    data/         58 fichiers · 4,9 Mo (+ dataset 192 Mo, historique 26 Mo)
    knowledge-base/ 32 JSON + documents/*.txt (graine de la table strategies)
    tools/        23 scripts de recherche (19 consomment api/), hors production
    ml/           2 scripts Python (baseline.py, entrainer.py) + __pycache__
    models/       2 JSON : modele-r.json (140 Ko), echantillon-parite.json (238 Ko)
    vendor/       reactbits (7 fichiers, composants UI)
    state/        3 dossiers VIDES (data/, knowledge-base/, uploads/) — cible volume Docker
    logs/         out.log 596 o, err.log 0 o (non exploités, pas de rotation)
    .codex/       skills de l'agent, aucun code exécuté par l'app
    .github/      workflows/verifier.yml (CI ajoutée le 2026-11-02)

### Ce que chaque dossier fait vraiment

- **api/** : tout le backend. Pas de dossier `models/`, `controllers/`, `routes/`.
  101 routes déclarées dans `server.js` ; la logique est dans les modules voisins,
  appelés directement. Un module = une préoccupation (`signals.js` moteur à règles,
  `signaux.js` moteur multi-signaux, `market.js` données, `frais.js` coûts…).
- **frontend/** : `index.html` contient toute l'application React (compilée dans le
  navigateur par Babel). `lightweight-charts.js`, `font-awesome.min.css`,
  `design-tokens.css`, `theme.js`, `sw.js`, `reactbits.jsx` sont bien chargés.
  `prototype-redesign.html`, `logo.svg`, `logo-current.svg` : **jamais référencés**.
- **data/** : état applicatif JSON (lexique, alertes, frais, risque, journal) +
  `dataset/` (192 Mo) et `historique/` (26 Mo) qui sont des données de recherche,
  exclues de l'image Docker. Résidus : `signaux-journal.json.4888.tmp`,
  `.avant-heritage`, `.avant-peremption`.
- **knowledge-base/** : 32 JSON (`concept_*`, `man_*`, `srch_*`) + 5 `.txt`. C'est la
  graine qui alimente la table `strategies` au premier démarrage.
- **ml/**, **models/**, **tools/** : recherche et calibration. `tools/` n'est importé
  par aucun module de production ; `ml/entrainer.py` produit `models/modele-r.json`,
  lu par `api/modele.js`.
- **state/** : vestige du déploiement Docker (`DATA_DIR=/app/state/data`). Sur
  Hostless le disque est en lecture seule, `api/dossiers.js` bascule donc sur
  `/tmp/5trade`. Le dossier reste vide localement.

## 3. Architecture réelle : deux mondes parallèles

### Monde A — le chemin IA (celui de l'écran « Analyse »)

    POST /api/analyze            server.js:1791
    POST /api/market/analyze     server.js:2699
       → Market.getCandles(…)           market.js  (REST/WS + cache)
       → Structure.analyze(…)           structure.js
       → searchKnowledgeBase(all,…)     server.js:1863   ← sélection par TEXTE
       → buildPlan({strategies})        server.js:1894
           → deepseek(… json:true)      server.js:1969
           ← {"action","confidence","entry","stopLoss","objectifs"}

`searchKnowledgeBase` (server.js:1863) note chaque stratégie par correspondance de
sous-chaînes : `text.includes(pair)` → +4, `text.includes(tf)` → +2, recouvrement
de mots +0,6, tags +1,5. **C'est une recherche, pas une exécution.**

`buildPlan` demande explicitement au modèle : `"action": "BUY|SELL|HOLD|WAIT"`,
`"entry"`, `"stopLoss"`, objectifs. **Sur ce chemin, les niveaux de trading sont
produits par l'IA**, à partir de textes de stratégies.

### Monde B — le chemin déterministe (alertes, journal, backtest)

    alerts.js:564  setInterval → verifier()
       → deps.market.getCandles             market.js
       → deps.signals.detect(closes,{symbol,timeframe})      alerts.js:414
       → deps.signaux.detecterTout(closes,meta,{profils})    alerts.js:426
       → deps.journal.enregistrer(...)                        journal-signaux.js
       → garde-fous force/contradiction/confluence            alerts.js:430-470
       → sendTelegram(...)                                    alerts.js
    puis journal-signaux.evaluer() / mettreAJour() → résultat tp1/tp2/sl/be/expire + R

Ici les niveaux, le R et le résultat sont calculés en JavaScript. L'IA n'intervient pas.

## 4. Parcours complet d'un signal (fichier · fonction · ligne)

| # | Étape | Fichier | Fonction |
|---|---|---|---|
| 1 | Config alertes (fichier + base + env) | `api/alerts.js` | `load()`, `hydrater()` |
| 2 | Boucle périodique (60 s) | `api/alerts.js:564` | `start()` → `verifier()` |
| 3 | Récupération des bougies | `api/market.js` | `getCandles()` (Binance REST / Deriv WS, cache) |
| 4 | **Verdict principal** | `api/signals.js` | `detect(closes,{symbol,timeframe})` — **sans stratégie** |
| 5 | Liste multi-signaux | `api/signaux.js` | `detecterTout(closes,meta,{profils})` |
| 6 | Journalisation | `api/journal-signaux.js` | `enregistrer()` |
| 7 | Garde-fous | `api/alerts.js` | force ≥ `forceMin`, contradiction, confluence multi-TF (l.469), RR |
| 8 | Envoi | `api/alerts.js` | `sendTelegram()` → `api.telegram.org` |
| 9 | Évaluation du signal | `api/journal-signaux.js` | `evaluer()`, `mettreAJour()`, `perimer()` |
| 10 | Statistiques | `api/journal-signaux.js` | `stats()` → `parStrategie`, `combinaisons`, `calibration` |

Deux maillons de ton schéma n'existent pas dans ce parcours : la **vérification de
compatibilité actif/stratégie** (absente partout) et le **filtrage des actualités**
(appelé seulement dans le Monde A, `server.js:1759`).

## 5. Les dix vérifications demandées

**1. Chaque stratégie possède-t-elle ses propres règles ? — NON.**
31 lignes en base, champs réels : `id, type, title, content, tags, createdAt`
(+`source`, `sourceUrl`, `structured`, `moteur`). Répartition : 12 `strategy`,
15 `web-strategy`, 4 `concept`. **Une seule** porte un `moteur` exécutable
(« Scalping sweep + FVG/OB sur indices synthétiques » : `regles:[R1,R3]`,
`atrStop:1`, `seuilForce:0.5`, `timeframes:["1m"]`, `seuilRegles:2`, `swingsWindow:2`).
Les 16 `structured` contiennent `{"error":"DEEPSEEK_API_KEY non configurée","rules":{}}` :
l'extraction de règles a échoué à l'import et n'a jamais été rejouée.

**2. Le système exécute-t-il les règles de la stratégie sélectionnée ? — NON pour la décision.**
`alerts.js:414` : `deps.signals.detect(closes, { symbol, timeframe })` — aucun profil
passé. C'est ce verdict `v` qui décide (`v.status === 'confirme'`, `v.strength >= forceMin`,
`v.contradiction`, puis confluence par `detect()` aux autres TF, `alerts.js:469`).
Les stratégies cochées n'arrivent qu'à la ligne 426, dans `detecterTout(…, {profils})`,
c'est-à-dire dans **le contenu du message**, pas dans le déclenchement.

**3. Une stratégie peut-elle être liée à une paire précise ? — NON.**
Aucune affectation. `searchKnowledgeBase` fait `text.includes(pair)` (+4 points) :
si le mot « EURUSD » figure dans le texte, la stratégie est jugée pertinente.
`grep -i compatib` sur `api/*.js` ne renvoie que « S3-compatible » et
« compatible = z.sens === sens » (direction d'une zone). Zéro contrôle de compatibilité.

**4. Le timeframe est-il vérifié ? — NON.**
Même mécanisme : `text.includes(tf)` (+2 points). Aucune liste de TF autorisés par
stratégie, aucun refus. Un TF non prévu par la stratégie peut être analysé.

**5. Toutes les conditions obligatoires sont-elles contrôlées ? — NON.**
`signals.detect` produit une `checklist` et un score de force continu. Le seuil
d'émission est `force >= c.forceMin` (0,65) : c'est une **moyenne pondérée**, pas une
conjonction. Rien ne marque une condition comme obligatoire ; deux conditions à 0,9
compensent une condition critique à 0.

**6. Que se passe-t-il si une condition manque ?**
- Monde B : le signal est écarté par `continue` et la raison est poussée dans
  `resultats.push({verdict: "…"})` — utilisée pour l'écran de vérification, **non
  persistée** dans le journal. On ne peut pas reconstituer après coup pourquoi un
  signal n'est pas parti.
- Monde A : le modèle répond `HOLD`/`WAIT`. Non déterministe, non reproductible.

**7. Les actualités peuvent-elles bloquer un signal ? — PARTIELLEMENT.**
`filtreCalendrier()` (`fundamentals.js:113`) n'est appelé qu'en `server.js:1759`
(chemin IA). **Jamais dans la boucle d'alertes** : un signal peut partir sur Telegram
pendant une publication NFP. Détail : la devise est déduite par
`symbol.slice(0,3)`, donc `R_75` → `R_7` — sans effet sur les synthétiques, mais par
accident, pas par conception.

**8. L'IA valide-t-elle les résultats ou les commente-t-elle ? — ELLE DÉCIDE (Monde A) / COMMENTE (Monde B).**
Monde A : `buildPlan` lui demande `action`, `entry`, `stopLoss`, objectifs → elle
produit les niveaux. Monde B : elle n'est pas appelée du tout. Aucune fonction ne
confronte une réponse d'IA aux conditions calculées : il n'existe pas de « juge ».

**9. Le backtest reproduit-il fidèlement le moteur réel ? — OUI pour le moteur multi.**
`backtest.js` importe `./signaux` et `./journal-signaux` et appelle
`Multi.detecterTout` (l.104) puis `Journal.evaluer` : **les mêmes fonctions que le
live**. Limite : il ne teste que le Monde B, et il hérite du même problème de
`moteur` quasi inexistant. Le Monde A (IA) n'est pas backtestable.

**10. Les statistiques permettent-elles d'évaluer chaque stratégie ? — PARTIELLEMENT.**
`journal-signaux.stats()` expose `parStrategie`, `combinaisons` (strategy × marché × TF,
seuil de 10 trades) et `calibration`. Mais **`strategie` vaut `null` sur les 800
signaux du journal** : ils viennent des motifs et de la structure, pas de stratégies
nommées. En pratique, les lignes de `parStrategie` sont donc des familles de motifs,
pas des stratégies de la base.

## 7. Problèmes détectés et risques techniques

### P0 — faussent le produit

1. **L'IA produit les niveaux de trading** sur `POST /api/analyze` et
   `POST /api/market/analyze` (`buildPlan` → `deepseek`, `server.js:1969`). Le
   résultat n'est pas reproductible, non backtestable, et dépend d'un texte.
2. **La décision d'alerte ignore la stratégie sélectionnée** (`alerts.js:414`). Le
   `go/no-go` est générique ; la stratégie ne change que le libellé du message.
3. **Aucune compatibilité stratégie ↔ marché ↔ timeframe.** Rien n'empêche
   d'appliquer une méthode Forex à un indice synthétique.
4. **30 des 31 entrées ne sont pas exécutables.** L'interface les présente comme des
   stratégies ; la base contient surtout de la documentation (`content`).
5. **Aucune condition n'est « obligatoire »** : le seuil est un score (force ≥ 0,65),
   donc une condition critique absente peut être compensée.

### P1 — dette structurelle

6. `server.js` : 3 920 lignes, 101 routes, point de couplage unique.
7. **Deux moteurs aux sémantiques proches** (`signals.js` règles R1..R4,
   `signaux.js` multi-signaux). Les deux sont appelés dans la même boucle, avec des
   définitions de « confirmé » différentes.
8. `structured` rempli d'erreurs d'extraction (`DEEPSEEK_API_KEY non configurée`),
   et le scoring de `searchKnowledgeBase` donne +2 points à une stratégie qui a des
   `rules` — donc un `structured` vide est **pénalisé**, pas signalé.
9. Actualités absentes de la boucle d'alertes, et devise déduite par `slice(0,3)`
   (faux pour `R_75`, `BTCUSDT`, `frxXAUUSD`).
10. Dépendance CDN au runtime : React, ReactDOM, Babel, Tailwind, Font Awesome,
    Google Fonts chargés depuis Internet à chaque ouverture.

### P2 — hygiène

11. `verify.js` : 3 589 lignes, un seul fichier de tests.
12. Fichiers morts et résidus `.tmp`/`.avant-*` versionnés.
13. `logs/` non exploité (aucune rotation, `err.log` vide).
14. Pas de rétention des sauvegardes R2, pas d'alerte si un envoi échoue.
15. Limiteur de connexion en mémoire (8 tentatives / 10 min, remis à zéro au déploiement).

## 9. Recommandations, par priorité

**Semaine 1 — arrêter la fuite (aucune réécriture)**

1. Décider du rôle de l'IA : sur le chemin d'analyse, elle **explique** et ne produit
   plus `entry`/`stopLoss`/`objectifs`. Ces champs viennent du moteur ou ne sortent pas.
2. Passer le profil de la stratégie sélectionnée à `detect()` (`alerts.js:414`), pas
   seulement à `detecterTout()`. Une ligne de câblage, vérifiable par un test.
3. Introduire un refus explicite : `moteur` absent ⇒ stratégie marquée
   « documentaire », non sélectionnable pour une analyse.

**Semaine 2-3 — rendre les stratégies exécutables**

4. Figer le schéma `moteur` (l'unique exemple existant sert de référence) : id,
   version, marchés, timeframes, règles nommées avec `obligatoire: true|false`,
   paramètres, état (`brouillon|testée|validée`).
5. Classer les 31 entrées : exécutables / à convertir / documentation. Les
   `web-strategy` et `concept` sortent du sélecteur d'analyse.

**Semaine 4 — compatibilité et diagnostic**

6. Matrice `stratégie × marché × timeframe` en données, vérifiée avant exécution,
   avec refus motivé (jamais silencieux).
7. Persister les conditions **nommées** avec leur statut sur chaque analyse, et un
   écran de diagnostic qui affiche la condition bloquante.

**Ensuite** — cycle de vie complet, `strategy_performance` alimentée par le journal,
tests à scénarios de marché injectés.

**Ce qu'il ne faut pas faire** : ajouter des stratégies, des indicateurs ou des
modèles avant l'étape 4. Le 2026-11-02, un modèle de fondation (Kronos) a été mesuré
puis écarté : directional accuracy 48,3 % et −5,69 pb/trade sur 297 origines réelles
(`docs/KRONOS.md`). Le manque n'est pas la matière première, c'est l'exécution traçable.
